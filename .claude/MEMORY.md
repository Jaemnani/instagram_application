# 키딩성수 — 작업 이력

> 손대기 전 규칙은 루트 `CLAUDE.md` 참조. 여기는 "왜 그렇게 됐는지"의 기록이다.

## 2026-08 풀페이지 스냅 도입 (nob-sakuma.com 참고)

참고 사이트: https://nob-sakuma.com/ — 스크롤 스테이트먼트, 마퀴 리본, 다크 갤러리,
대형 CONTACT. 기존 에디토리얼 톤(ivory/ink/clay + Noto Serif)은 유지하고 플레이풀
포인트만 절제해서 얹기로 결정.

**장면 구성** (휠 한 번에 한 장면)
```
히어로 → 스테이트먼트 → 스토리+서비스 → 갤러리(가로) → FAQ → 오시는 길 → BOOK NOW → 푸터
```

**시행착오 — 넣었다가 뺀 것**
- **조리개(IrisReveal)**: 예약 화면이 원으로 열리는 연출. 도착 후 열리게 타이밍까지
  맞췄으나(스크롤 정착 감지), 아래 셔터로 흡수됐다가 함께 제거.
- **셔터(ShutterTransition)**: 곰돌이를 화면 고정 오버레이로 만들어, 오시는 길 화면
  위에서 조리개가 열리고 닫히며 예약이 드러나게 했다. 화면 이동은 조리개가 덮은
  동안에만 일어나 완벽히 감춰졌다. **하지만 그 구간에서만 휠을 가로채므로 장면마다
  휠 반응이 달라져 사용자가 "차라리 없는 게 낫다"고 판단.** 연출 < 조작 일관성.
- **곰돌이·카메라 장면**: 셔터 제거 후 평범한 장면으로 되돌렸다가, 사용자 요청으로 제거.
  갤러리 상단의 곰돌이 스티커는 별개이므로 유지.

**남은 연출**: 스테이트먼트 단어 순차 점등, 마퀴 리본, 가로 갤러리(휠 위임),
아치 커튼(섹션 경계 둥근 모서리 + 음수 마진), 백드롭 아웃라인 타이포, 마스킹테이프 날짜.

## 겪은 문제와 원인 (같은 증상 재발 시 여기부터)

| 증상 | 진짜 원인 |
|---|---|
| 휠 돌린 만큼만 움직임, 한 장면씩 안 넘어감 | 스냅이 꺼짐. `min-height: 760px` 이 13" 노트북 뷰포트(~750px)보다 높았다 → 640 으로 하향 |
| 고쳤는데 그대로 (CSS만) | Turbopack 이 옛 CSS 서빙. `.next` 삭제 필요. **2회 발생** |
| 스크롤이 스르륵 흘러감 | 장면이 뷰포트보다 큼(1280×800 에서 갤러리 952px) |
| 특정 지점에서 갇힘 | `position: sticky` × `scroll-snap-align` 조합 |
| 갤러리에서 아래로 못 감 | 가로 스트립이 세로 휠을 삼킴. 끝에 닿아도 브라우저가 페이지로 안 넘겨줌 → 다음 장면으로 직접 이동 |
| 연출이 "사라짐" | 코드는 있는데 스냅 이동 중에 애니메이션이 다 끝나 도착 시점엔 완료 상태 |

## 사용자 협업 규칙 (반복 지적된 것)

1. **수정할 때마다 브라우저로 직접 보고 검증** — JS 점프 말고 실제 휠, 부분 말고 전체 완주,
   한 창 말고 여러 화면 크기.
2. **빼달라고 하지 않은 연출·기능은 지우지 않는다.** 새 요청은 "추가"로 해석한다.
   (조리개를 곰돌이 장면 넣으며 지웠다가 지적받음.)
3. 커밋은 자유, **푸시는 명시 요청 시에만.**
