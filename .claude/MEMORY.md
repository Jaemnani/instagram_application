## 2026-08 풀페이지 스냅 도입 (nob-sakuma.com 참고)

참고 사이트: https://nob-sakuma.com/ — 스크롤 스테이트먼트, 마퀴 리본, 다크 갤러리,
대형 CONTACT. 기존 에디토리얼 톤(ivory/ink/clay + Noto Serif)은 유지하고 플레이풀
포인트만 절제해서 얹기로 결정.

**장면 구성** (휠 한 번에 한 장면)
```
히어로 → 스테이트먼트 → 스토리+서비스 → 갤러리(가로) → FAQ → 오시는 길 → BOOK NOW → 푸터
```

**시행착오 — 넣었다가 뺀 것**
- **조리개(IrisReveal)**: 예약 화면이 원으로 열리는 연출. 도착 후 열리게 타이밍까지
  맞췄으나(스크롤 정착 감지), 아래 셔터로 흡수됐다가 함께 제거.
- **셔터(ShutterTransition)**: 곰돌이를 화면 고정 오버레이로 만들어, 오시는 길 화면
  위에서 조리개가 열리고 닫히며 예약이 드러나게 했다. 화면 이동은 조리개가 덮은
  동안에만 일어나 완벽히 감춰졌다. **하지만 그 구간에서만 휠을 가로채므로 장면마다
  휠 반응이 달라져 사용자가 "차라리 없는 게 낫다"고 판단.** 연출 < 조작 일관성.
- **곰돌이·카메라 장면**: 셔터 제거 후 평범한 장면으로 되돌렸다가, 사용자 요청으로 제거.
  갤러리 상단의 곰돌이 스티커는 별개이므로 유지.

**남은 연출**: 스테이트먼트 단어 순차 점등, 마퀴 리본, 가로 갤러리(휠 위임),
아치 커튼(섹션 경계 둥근 모서리 + 음수 마진), 백드롭 아웃라인 타이포, 마스킹테이프 날짜.

## 겪은 문제와 원인 (같은 증상 재발 시 여기부터)

| 증상 | 진짜 원인 |
|---|---|
| 휠 돌린 만큼만 움직임, 한 장면씩 안 넘어감 | 스냅이 꺼짐. `min-height: 760px` 이 13" 노트북 뷰포트(~750px)보다 높았다 → 640 으로 하향 |
| 고쳤는데 그대로 (CSS만) | Turbopack 이 옛 CSS 서빙. `.next` 삭제 필요. **3회 발생** (2026-09-30 은 되돌린 CSS 가 반영 안 됨) |
| 게시물 상세에서 휠 한 번에 바닥 | 스냅이 전역이라 장면 없는 페이지의 유일한 안착점(푸터)으로 끌림 → `html:has(.snap-page)` |
| 스크롤이 스르륵 흘러감 | 장면이 뷰포트보다 큼(1280×800 에서 갤러리 952px) |
| 특정 지점에서 갇힘 | `position: sticky` × `scroll-snap-align` 조합 |
| 갤러리에서 아래로 못 감 | 가로 스트립이 세로 휠을 삼킴. 끝에 닿아도 브라우저가 페이지로 안 넘겨줌 → 다음 장면으로 직접 이동 |
| 연출이 "사라짐" | 코드는 있는데 스냅 이동 중에 애니메이션이 다 끝나 도착 시점엔 완료 상태 |

## 2026-09-30 통합 예약 캘린더 (진행 중)

**목표**: 네이버 예약·스페이스클라우드·아워플레이스·구글·애플 캘린더를 합쳐 한 곳에서
빈 시간을 계산하고, 사이트에서 직접 예약 신청을 받는다.

**조사 결과 (근거는 세션 조사, 확인/미확인 구분)**
- 네이버 예약: 사장님용 공개 API·iCal 없음(제휴사 149곳 전용). 사장님 확인으로 **네이버
  캘린더에 예약이 들어온다** → 네이버 캘린더 CalDAV(`caldav.calendar.naver.com`, 제3자 가이드
  기준)로 읽을 계획. 네이버 쪽 시간을 막는 자동 수단은 여전히 없음 → 승인 시 수동.
- 아워플레이스: iCal 가져오기·내보내기 둘 다 → 양방향 자동 (가져오기 반영 최대 30분)
- 스페이스클라우드: iCal 내보내기만 → 읽기 자동, 막기는 수동
- 구글: 서버가 "비공개 iCal 주소"를 직접 읽음(즉시 최신). 앱의 'URL로 구독'은 12~24h 늦어 쓰면 안 됨
- 애플: 공개 캘린더 링크(webcal) 읽기
- 추가 채널 후보: Airbnb 서비스(구글 캘린더 OAuth 경유), Cal.com(iCal 가져오기 유일), Bokun/Rezdy(Klook 등 OTA)

**확정 규칙(사장님)**: 시작 30분 단위 · 상품 1h/2h · 예약 사이 30분 텀(외부 일정에도 적용)
· 우리 사이트 예약은 "신청 → 사장님 승인 → 확정"(A안: 자체 DB + 승인).

**단계**
1. ✅ 빈 시간 엔진 + 외부 iCal 합치기 + `/[lang]/book` (지금은 카카오톡 문의로 연결)
2. 신청 저장 — **NAS 자체호스팅 Supabase**(knowai 운영 DB 사용 금지). `jeremylab.synology.me:5051`
   은 DSM 로그인 화면이었다 → Supabase API(Kong) 외부 주소를 따로 열어야 함. NAS 의 pg_cron 으로
   5~10분 동기화(Vercel Hobby 는 cron 1일 1회라 불가). Vercel 함수 리전을 icn1 로.
3. 관리자 통합 캘린더 · 승인 · 네이버 체크리스트 / 4. 구글 기록 + 알림 / 우리 iCal 피드 출력

**설계 메모**: 텀은 바쁜 구간 쪽을 양옆으로 부풀려 비교(`slots.ts conflicts`). 종일 일정은
node-ical 이 서버 로컬 0시로 만드므로 로컬 getter 로 날짜를 뽑아 KST 하루를 막는다 —
UTC/KST/LA 세 타임존에서 검증함. 캘린더 하나가 죽으면 예약은 열되 `degraded` 로 알린다
(최종 관문은 사장님 승인).

## 2026-10-09 갤러리 구조 정리 (C안)

- **숨김 목록** `data/curation.json` — 공지·포스터를 사람이 직접 고른다(해시태그 자동 기준은 캡션 깜빡하면 샘).
  `getInstagramData` 한 곳에서 걸러 상세·사이트맵·llms.txt 까지 같이 빠진다. 형식이 깨지면 빌드가 멈춘다
  (try 밖에서 읽음 — 안쪽 catch 가 삼키면 "게시물 0개"로 조용히 바뀜).
- **홈 스트립 최근 12개**(`STRIP_LIMIT`) + 끝 칸 "+N 전체 보기" + 아래 줄 "전체 보기" 링크.
  끝 칸 높이 = 카드 사진 칸(`md:h-[27svh]`) — 더 크면 갤러리 장면이 화면을 넘는다.
- **`/[lang]/gallery`** 전체 격자. 일반 스크롤 페이지(스냅 장면 없음).
- **자동 반영**: cron → `/api/sync` → 토큰 확인 → `DEPLOY_HOOK_URL` 재배포 → prebuild(sync).
  ⚠️ 2026-10 이전엔 Vercel 에 `CRON_SECRET` 이 없어 cron 이 매일 503 이었다(아무것도 안 함).
- **측정 함정**: Playwright `mouse.wheel` 은 mandatory 스냅을 다음 장면으로 못 넘긴다(단순 스냅 페이지도
  120px → 2px 로 복귀). 스냅 완주 측정은 휠 한 칸을 `innerHeight*0.6` 으로.
- **미해결 버그(기존)**: 가로 스트립 휠 위임의 `el.scrollLeft += deltaY` 가 `snap-x snap-mandatory` 에
  의해 매번 0 으로 되돌아간다 — 마우스 100px·트랙패드 4px 로는 한 칸도 안 넘어감. `scrollBy` 는
  방향 스냅이라 한 장(274px)씩 넘어간다(실측).

## 사용자 협업 규칙 (반복 지적된 것)

1. **수정할 때마다 브라우저로 직접 보고 검증** — JS 점프 말고 실제 휠, 부분 말고 전체 완주,
   한 창 말고 여러 화면 크기.
2. **빼달라고 하지 않은 연출·기능은 지우지 않는다.** 새 요청은 "추가"로 해석한다.
   (조리개를 곰돌이 장면 넣으며 지웠다가 지적받음.)
3. 커밋은 자유, **푸시는 명시 요청 시에만.**
