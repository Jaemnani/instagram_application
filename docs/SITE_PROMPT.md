# 의뢰: 인스타그램을 미러링하는 다국어 SEO/GEO 사이트

서울 성수동의 베이비·가족 사진 스튜디오 **kidding seongsu(키딩성수)** 의 공식 홈페이지를
만들어줘. 인스타그램 계정 `@kidding.seongsu` 의 게시물을 **공식 Graph API로 가져와**
정적 페이지로 미러링하는 구조다. 스크래핑이 아니라 본인 소유 계정의 공식 API다.

**이 사이트의 최종 목적은 사람 검색이 아니라 AI 검색이다.** ChatGPT·Perplexity 같은
생성형 엔진이 "성수동 돌사진 스튜디오 알려줘" 같은 질문에 이 업체를 근거로 답할 수 있어야
한다. 그래서 예쁜 화면보다 **구조화 데이터와 사실 정보의 정확성이 우선**이다.

## 기술 스택

- Next.js(App Router) + TypeScript strict + Tailwind CSS
- 전 페이지 정적 생성(SSG). 런타임 DB 없음
- 데이터는 빌드 시점에 `data/instagram.json` 하나로 동기화해 두고 페이지가 그걸 읽는다
- 이미지는 인스타 CDN을 직접 걸지 말고 빌드 때 내려받아 자체 호스팅한다(만료 URL 문제)

## 브랜드와 톤

- 표기는 **영문 소문자 `kidding seongsu`** 로 통일. 한국어 상호 `키딩성수`는
  구조화 데이터의 `alternateName` 과 한국어 본문 첫 언급에만 남긴다(한글 검색 신호 유지)
- 슬로건: **"No posed, Just Kidding!"** — "여기 보세요, 웃어보세요" 같은 연출을 거부하고
  아이가 노는 사이의 표정을 담는다는 철학
- 카피는 광고 문구처럼 쓰지 말 것. 담백하고 낮은 목소리로

## 디자인 방향 — 에디토리얼 매거진

인스타그램 UI를 흉내 내지 말 것(피드 그리드, 하트 아이콘 나열 등 금지).
잡지 레이아웃처럼 여백이 넓고 타이포그래피가 중심이 되는 화면으로.

**색 — 따뜻한 뉴트럴. 순수 검정·흰색을 쓰지 않는다**

```
ivory  50 #fdfcfa   100 #f8f5f0   200 #efe9e1   300 #ded4c8   (종이 느낌 배경)
ink   400 #8a8279   600 #5a534b   800 #2e2a26   900 #1c1917   (먹색 글자)
clay  500 #b4694e   600 #9a5640    50 #fbf1ed              (저채도 테라코타 액센트)
```

액센트를 테라코타로 잡은 이유는 아기 사진의 살구빛 피부톤과 부딪히지 않기 때문이다.

**서체 3종**

- 제목: Noto Serif KR (400/600/700) — 한글 세리프
- 본문: Noto Sans KR (400/500/700)
- 워드마크: 초경량 기하학 산세리프(Poppins 200/700 등). 라틴 전용이라 한글은 자동 폴백

한글 세리프 제목은 자간이 벌어져 보이므로 `letter-spacing: -0.02em` 로 조인다.

**연출**

- 스크롤 시 요소가 아래에서 떠오르는 등장 효과(IntersectionObserver, 18px + opacity)
- `prefers-reduced-motion: reduce` 면 효과 자체를 적용하지 않는다
- JS가 없으면 `<noscript>` 로 항상 보이게 되돌린다 — **크롤러에게 빈 화면이 보이면 안 된다**

## 페이지 구성

```
/[lang]                     한 페이지 구성 (아래 6개 섹션)
/[lang]/posts/[slug]        게시물 상세
/[lang]/privacy             개인정보 처리방침
/robots.txt  /sitemap.xml  /llms.txt  /opengraph-image
```

헤더 내비게이션은 **두지 않는다**. 한 페이지 안에서 스크롤로 읽히게 하고,
하위 페이지에는 좌상단에 워드마크 로고를 홈 링크로 둔다.

**홈 6개 섹션**

1. **히어로** — 전체 화면(`min-h-svh`) 사진 배경 + 가운데 대형 워드마크.
   그 아래 그 언어의 검색어 한 줄, 예약 버튼 하나, `SCROLL` 신호.
   배경 사진은 **최신 게시물이 아니라 좋아요가 가장 많은 게시물**을 쓴다
   (최신은 이벤트 포스터일 때가 많다). env로 특정 게시물 지정도 가능하게
2. **이야기** — 스튜디오 소개 3꼭지
3. **촬영 종류** — 4개를 01~04 번호와 함께 **한 화면에 전부** 표시(더보기 없이).
   순서: `01 돌사진 촬영` `02 백일·성장 사진` `03 가족사진` `04 렌탈 스튜디오`
4. **최근 촬영** — 대표 게시물 1장을 크게, 그 아래 나머지를 **가로 스크롤 스트립**으로
5. **자주 묻는 질문** — 7문답
6. **오시는 길** — 주소·영업시간·교통편·편의시설 + 예약 CTA

**화면 밖으로 나가는 버튼은 "촬영 예약 문의" 하나뿐이다.** 나머지는 전부 같은 페이지 안에서
해결한다.

## 다국어 — 한국어·영어·일본어·중국어(간체)

- `app/[lang]/` 라우트 + 미들웨어가 `Accept-Language` 를 보고 접두사 없는 요청을 배분.
  지원하지 않는 언어는 한국어로
- 사전은 언어별 파일 하나씩. **한국어 사전에서 타입을 파생시켜** 다른 언어에 키가 빠지면
  컴파일이 실패하게 만들 것
- UI 라벨만이 아니라 **서비스 설명·FAQ·스튜디오 이야기·개인정보처리방침 전문**까지 번역
- **검색어는 언어별로 다르게 쓴다.** 직역하지 말 것 —
  영어권은 `Seoul baby photo studio`, 일본어권은 `ソウル ベビーフォト`,
  중국어권은 `首尔儿童摄影工作室` 처럼 그 언어권이 실제로 검색하는 말로
- **중국어에 라틴 단어를 섞지 말 것.** `studio` 가 아니라 `工作室`
- 게시물 캡션도 번역하되 원칙이 있다(아래 "캡션 번역" 참조)

## 캡션 번역 원칙

인스타 캡션을 그대로 옮기면 웹사이트에서는 **틀린 정보**가 된다. 다음을 걷어낸다.

- 지난 예약 공지("4월 예약 오픈 안내") — 몇 달 뒤에 읽으면 잘못된 안내다
- 카카오톡 채널명, "프로필 하단 링크 클릭" — 인스타 안에서만 뜻이 통한다.
  사이트에는 모든 언어에 예약 버튼이 이미 있다
- 캡션 끝 해시태그 덩어리 — 화면에서 칩으로 따로 보여주므로 중복이다

반대로 **원문이 이미 영어인 문장은 글자 그대로 둔다**(`We're just kidding` 등).
해시태그도 번역하지 않는다 — 인스타 검색과 연결되어야 한다.

번역 결과는 **파일로 커밋해 두고 빌드는 읽기만** 하게 할 것. 배포 환경에 번역용
자격증명을 두지 않기 위해서다. 원문 캡션의 해시를 같이 저장해, 캡션이 수정되면
재번역 대상으로 잡히게 한다.

## SEO / GEO

**구조화 데이터(JSON-LD)** — 이 사이트의 핵심이다.

- `Organization` / `WebSite` — 전 페이지
- `LocalBusiness` — 주소(PostalAddress)·좌표(GeoCoordinates)·영업시간
  (`OpeningHoursSpecification`, 문자열 말고 구조화 형식)·`areaServed`·`hasMap`·
  `amenityFeature`·`knowsLanguage`(4개 언어)·`potentialAction`(ReserveAction)
- `OfferCatalog` + `Offer`/`Service` — 촬영 종류 4개
- `FAQPage` — AI가 질문·답변 쌍을 그대로 인용하기 가장 좋은 형식
- 게시물 상세: `SocialMediaPosting` + `ImageObject` + `InteractionCounter` + `BreadcrumbList`
- 홈: `ImageGallery`

**`@id` 는 언어와 무관하게 하나로 유지한다.** 그래야 4개 언어 페이지가 같은 업체로 묶인다.
`inLanguage` 만 언어별로 다르게.

**그 외**

- `hreflang` 4개 + `x-default`(한국어), canonical, `og:locale` / `alternateLocale`
- sitemap은 언어 × 문서 전부(각 항목에 `alternates.languages`)
- robots.txt에 GPTBot·OAI-SearchBot·ChatGPT-User·PerplexityBot·ClaudeBot·
  Google-Extended 명시 허용
- `/llms.txt` — 게시물 목록만이 아니라 "무슨 서비스를, 어디서, 언제, 어떻게 예약하는지"까지
- **IndexNow** — 키 파일을 `public/` 에 정적 파일로 두고(공개 소유 증명이라 비밀이 아니다),
  배포 후 URL 전체를 제출하는 스크립트. ChatGPT 검색이 Bing 인덱스 위에서 돌기 때문에
  신규 도메인의 발견 시간을 크게 줄인다
- **OAI-SearchBot은 JavaScript를 실행하지 않는다.** 본문이 JS 없이 HTML에 다 들어있어야 한다

**사실 정보 원칙**: 확인되지 않은 정보(가격, 촬영 시간, 보정본 장수)는 **넣지 말 것**.
AI가 잘못 인용하면 실제 고객 문의로 이어진다.

## 반드시 지켜야 할 함정 (실제로 겪은 것들)

**1. `word-break: keep-all` 은 한국어에만 적용한다**

한글은 어절 사이에 띄어쓰기가 있어 "단어 중간에서 안 끊고 띄어쓰기에서 끊는다"가 성립한다.
그런데 **일본어·중국어에는 띄어쓰기가 없어서, 문장 전체가 끊을 수 없는 한 덩어리가 되어
화면 밖으로 넘친다.** 실측으로 같은 일본어 제목의 최소 폭이 `keep-all` 357px ↔ `normal` 36px.

```css
:lang(ko) .font-serif { word-break: keep-all; }
```

**2. 대형 워드마크 크기를 브레이크포인트로 계단식으로 키우지 말 것**

`sm:` `lg:` 로 글자만 확 커지고 화면은 아직 좁은 구간이 생겨 잘린다(실측 320~415px,
640~723px). `nowrap` 이라 줄바꿈으로 흡수되지도 않는다. 화면 폭에서 좌우 여백을 뺀 값에
비례시킬 것.

```css
font-size: clamp(1.5rem, calc((100vw - 4rem) / 10), 5.5rem);
```

**3. 가로 스크롤 스트립의 `scroll-padding` 은 `padding` 과 같은 값이어야 한다**

없으면 `snap-start` 가 첫 카드를 padding 안쪽에 맞추려고 스크롤 위치를 padding 만큼 밀어놔,
**처음부터 "왼쪽 끝이 아닌" 상태가 되고 이전 화살표가 영원히 활성으로 남는다.**

**4. 사전(dict)을 클라이언트 컴포넌트에 통째로 넘기지 말 것**

`photoCount(n)` 같은 함수가 들어 있으면 "Functions cannot be passed to Client Components"
로 빌드가 깨진다. 서버에서 문자열로 만들어 넘긴다.

**5. 지도 링크는 좌표가 아니라 주소 문자열로 건다**

좌표로 링크하면 좌표의 오차가 그대로 핀 위치가 된다(수십 m만 틀려도 옆 건물을 가리킨다).
주소를 넘겨 지도 서비스가 건물을 직접 찾게 한다. 도로명주소가 지도에서 잘 안 잡히면
지번 주소를 따로 지정할 수 있게 할 것.

**6. 한국어 외 화면에는 로마자 주소를 함께 보여준다**

라벨과 교통편은 번역해놓고 주소만 한글이면, 외국인은 도시조차 알 수 없다.
로마자를 먼저 보여주고 한글은 "지도·택시 입력용"으로 병기한다 — 국내 지도 앱과 택시에는
한글 원문이 필요하고 로마자로는 검색이 안 되는 경우가 많다.
**단, 구조화 데이터의 주소는 한글 정본 그대로** 둔다(등록된 업체 정보와 글자가 같아야
검색엔진이 같은 업체로 묶는다).

**7. 라이트박스 이미지는 `fill` + `object-contain` 으로**

`width`/`height` + `w-auto` 는 브라우저의 밀도 보정 intrinsic 크기를 따라가 실제의
40% 로 렌더된다.

**8. 갤러리를 자동으로 흐르게 하지 말 것**

카드가 전부 링크라서 움직이는 대상은 누르기 어렵고, 무한 루프는 목록을 복제해야 해
같은 링크가 두 번 잡힌다(SEO·스크린리더 모두 손해). 대신 **다음 카드가 잘려 보이게 하고
(peek), 끝에 그라데이션을 깔고, 화살표를 둔다** — 세 겹으로 알린다.

## 접근성

- 스크롤 스트립에 `role="region"` + `aria-label` + `tabIndex={0}` (키보드 좌우 이동)
- 화살표는 양 끝에서 `disabled`, 스크롤할 것이 없으면 아예 숨긴다
- 한글 원문을 다른 언어 페이지에 병기할 때 `lang="ko"` 를 붙인다(스크린리더 발음)
- 라이트박스: ESC 닫기, 좌우 키 이동, 배경 스크롤 잠금

## 결과물

- 빌드가 통과하고 `tsc --noEmit`, lint 에러 0
- 4개 언어 × (홈 + 개인정보 + 게시물 N개) 전부 정적 생성
- 320px~1920px 어느 폭에서도 가로 스크롤이 생기지 않을 것
- JS를 끈 상태에서도 본문 전체가 읽힐 것
